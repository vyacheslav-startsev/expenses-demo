# Импорт банковской выписки — дизайн

## Зачем

Расходы по карте больше не вбиваются руками: пользователь загружает CSV-выписку из банка,
проверяет операции и сохраняет. Руками вносятся только наличные, поэтому ручные записи
и выписка не пересекаются.

## Цели

- Загрузить CSV в формате `samples/statement-2026-11.csv` и получить из него расходы.
- Перед сохранением показать экран проверки: что добавится, с какой категорией, что
  пропущено и почему; категорию можно поменять, строку можно снять галочкой.
- Повторная загрузка того же файла или пересекающейся выписки не задваивает расходы.

## Не цели

- Запоминать правки категорий пользователем (например «Кинопоток → Развлечения»). Позже.
- Другие форматы выписок и банки, другие валюты, кроме RUB.
- Сверка выписки с ручными записями: ручные записи — только наличные.
- Редактирование уже сохранённых расходов.

## Анти-цели

- В итог месяца не должны попасть зачисления, неуспешные операции и переводы между
  своими счетами без явного решения пользователя.
- Две настоящие одинаковые покупки (две чашки по 280 ₽ 9 ноября) не должны схлопнуться
  в одну.

## Подходы

1. **Без промежуточного хранения (выбран).** Загрузка → сервер разбирает файл и отдаёт
   страницу проверки; каждая строка несёт свои данные в скрытых полях формы, плюс выбор
   категории и галочка. «Сохранить» пишет отмеченные строки. Вписывается в нынешний стиль
   приложения (формы, POST, редирект). Минус: закрыл вкладку — загружай заново.
2. **Черновик импорта в базе.** Отдельная таблица с разобранными строками. Переживает
   перезагрузку, но лишняя таблица, чистка черновиков и больше кода ради выписки на пару
   десятков строк.
3. **Разбор в браузере на JS.** Отброшен: в проекте нет JS, всё рендерится на сервере.

Пользователь выбрал подход 1.

## Как устроено

**Формат файла.** UTF-8 (допускается BOM), разделитель `;`, заголовок как в образце.
Используются колонки: «Дата операции» (`ДД.ММ.ГГГГ ЧЧ:ММ:СС`), «Номер карты», «Статус»,
«Сумма операции» (запятая, расход со знаком минус), «Валюта операции», «Категория»,
«Описание». Дата расхода — дата операции, комментарий — «Описание». Если заголовок не тот
или строка не разбирается — понятная ошибка, ничего не сохраняется.

**Что с какой строкой.**

| Строка | На экране проверки |
|---|---|
| Статус не `OK` | пропущено: «не прошла» |
| Сумма больше нуля | пропущено: «зачисление» |
| Валюта не RUB | пропущено: «не рубли» |
| Уже есть в базе (по ключу) | пропущено: «уже загружено» |
| Категория банка «Переводы» | показана, галочка **снята** по умолчанию |
| Остальные расходы | показаны, галочка стоит |

**Ключ операции** — время операции + номер карты + сумма + описание. Новая колонка
`bank_ref` в `expenses` (у ручных записей `NULL`) с уникальным индексом; существующие
базы получают колонку при старте (`ALTER TABLE`, если её нет). Сохранение пропускает
строки, чей ключ уже есть, — на случай двойного нажатия.

**Категории** — фиксированная таблица в коде, всё неизвестное → «Другое»:

| Банк | Приложение |
|---|---|
| Супермаркеты | Продукты |
| Рестораны, Фастфуд | Кафе |
| Транспорт, Такси | Транспорт |
| Коммунальные услуги, Связь | Дом |
| Аптеки | Здоровье |
| Кино, Цифровые товары | Развлечения |
| остальное (Одежда и обувь, Переводы …) | Другое |

**Страницы.**
- На главной — блок «Загрузить выписку» с выбором файла.
- `POST /import` (файл) → страница проверки: сверху «N к добавлению, M пропущено»,
  список строк с галочкой, датой, описанием, суммой и выбором категории; ниже — пропущенные
  с причиной; кнопка «Сохранить».
- `POST /import/save` → сохраняет отмеченные строки, проверяя категорию и сумму так же,
  как ручной ввод, и редиректит на месяц самой поздней операции.

## Оставлено исполнителю

Разбиение кода по модулям (вероятно `app/statement.py` для разбора), разметка и стили
страницы проверки, точные тексты сообщений, набор тестов (разбор образца, правила
пропуска, повторный импорт, две одинаковые покупки, миграция старой базы).
